## 用户结果与范围

管理者和评审者进入对应租户后，可按真实页面的结构检查筛选、表格、配置和指定操作，并识别数据来源。不能以通用列表、其他租户的人员或推断的展开内容冒充当前租户实站。

范围为十七租户：佰智德三、锦帛美学、萌爪、诚如风险管理事务所、厚全鸡蛋、柚子烘焙；瑞熙小刘、小温、小周；艺星成都、深圳、北京、广州、杭州、嘉兴；画美医美-西安、傲丽医美-西安。当前导航库存为 **822 个租户页面入口、91 种路由**。其中783个为源环境队列，741个可见页有有效DOM与截图，42个按源隐藏；另有13个既有AI费用原型扩展、6个现有艺星回访规则及6个艺星辅助线管理入口，另有两新租户各3个待采集框架入口，以及本轮8个医美扫街轨迹原型入口，扩展项不计入实站采集。「工具管理」是结构父级，不新增业务页面路由。其他截图排除项、碎银私域和不可访问环境不自动纳入；画美/傲丽原独立页面框架仍按其已批准范围处理；2026-10-02仅平台全部账号状态内的微信账号总览及类型来源按ACCOUNT-TYPE-001@0.2.0核对，不等于两店全部业务页均已采集。各租户保留自己的可用入口、权限和独立显示配置；菜单表和侧栏按068共用有效完整树。平台allMenu提供默认顺序和归属，租户明确调过的同级列表及被移动项父级优先；073仅迁移工具/话术的指定层级，保留其他合法调整；平台当前祖先链隐藏/删除和既有权限始终约束可见导航。

## 工具管理与艺星辅助线

行为合同：[073@1.0.0](../docs/sdd/SPEC-SUIYIN-ADMIN-073/1.0.0/spec.md)，对应R001–R011。客户在后台自行维护PC图片编辑需要的辅助线，减少每次增加或替换素材都等待工程师改包的依赖；当前交付只验证本地管理与预览，不表示真实PC已经同步。

有原话术入口的既有15租户把原一级话术的位置替换为「工具管理」，话术成为其二级，`languageManage`链接、页签恢复、状态键和原有内容保持兼容。普通菜单、平台定义和侧栏使用相同结构；工具父级按可见子项展示，原话术隐藏与权限继续有效。迁移不重复添加话术，也不把工具统一追加到菜单末尾。平台可登记辅助线定义，但定义存在不向佰智德三等非艺星租户开放业务数据。

辅助线以艺星身份及显式能力登记开放，每个后台租户一套配置。当前验收覆盖深圳、成都、北京、广州、杭州、嘉兴六艺星；当前十一个非艺星无业务入口，直接地址也不能取得配置。六店是当前样例，不是生产白名单。来源标签只说明素材出处，系统默认与门店专属分类、图片均可在所属租户增删改。

| 管理对象 | 用户操作与约束 |
|---|---|
| 分类 | 新增、改名、删除、拖动或Alt＋上下键排序、启停；名称必填且同租户不能重名，新分类默认启用；删除确认明确影响图片数，取消不变 |
| 图片 | 批量添加透明PNG、改后台管理名称、替换、删除、拖动或键盘排序；不编辑PNG内部线条。替换成功前保留原图、身份、顺序和管理名称；相同源文件在不同分类仍为独立条目 |
| 逐项处理 | 每张不超过10MiB的原型示例上限；逐项显示校验、处理、成功、失败，可重试、重新选择或取消/移除；格式、超限、解码与模拟失败给可读原因。重试不重复追加，旧租户或已移除操作的迟到结果失效 |
| 页面草稿 | 所有操作先改草稿，明确点击保存才替换本租户本地配置；处理中或未解决的失败项阻止保存。保存中禁用重复提交，失败保留草稿和旧配置 |
| 清空与异常 | 首次未配置、已保存为空、全部停用、图片加载失败、配置读取失败分别表达；主动删除全部内容并保存后不恢复默认；损坏数据保持原值并提供重试 |

应用内切页、关闭业务页签、关闭其他页签或切租户时，有草稿或未解决的图片队列就提示「保存并离开 / 放弃更改 / 继续编辑」。保存失败留在当前页；放弃恢复已存配置并使未完成任务失效；继续编辑保留原草稿与队列。浏览器刷新/关闭只使用允许的原生离开提示，不承诺自定义三按钮，也不自动保存草稿。

「预览PC效果」读取当前草稿的独立副本，只展示启用分类及相同顺序，未保存内容明确标注。PC卡片保留业务分类名和纯缩略图，不显示后台管理名称、来源页或尺寸。透明图可以作为独立对象插入、拖动、等比缩放、旋转、删除与撤销；预览关闭不保存配置，也不改动真实PC客户端。

当前初始演示取自030本地共享目录，16类、129条、123个唯一PNG按租户独立初始化。尚未取得各店最新生产清单时，明确标注演示；数量不是配置不变量，用户增删改后允许不同。030既有PC版本的固定目录、原PPT来源和五城样例保留为当时交付合同，073仅继承其分类、纯缩略图与对象交互，不把旧范围排除套到新增Admin管理。原型不提供跨租户复制、恢复默认、真实上传、数据库迁移或跨端同步。

本地预览：[深圳辅助线管理](../prototype/_shell.html?tenant=yestar-sz&page=guideLineManage)。工程实现以073版本化[Handoff](../docs/sdd/SPEC-SUIYIN-ADMIN-073/1.0.0/issue-handoff.md)和[Test Contract](../docs/sdd/SPEC-SUIYIN-ADMIN-073/1.0.0/test-contract.md)为准；本地功能通过与生产完成分别验收。

等级按所选来源截至运行时最近一次真正进入目标等级的时间计算；人工与AI历史互不借用，同级重复评定不重置。后续等级变化不自动增加“当前仍为该等级”的限制，需要时由用户添加既有等级筛选。到店、购买、划扣分别先排除运行时点之后的事件，再取所选首次或最近一次；恰好运行时点可用，当天按北京时间第0天。

缺失或格式损坏的所选历史显示“无法判断”；明确完整空历史、没有目标等级进入事件或截至运行时尚未发生则“未入选”。不以当前等级、添加日期、预约日期或其他事件补猜。预约基准沿用原appointment日期值，不代表预约创建时间，也不新增逐条预约触发或取消规则。“划扣”可对应客户资料核销记录术语，但本页没有接通真实CRM；购买发生不等于按商品筛选。

第3、5、7天在列表中属于一条“添加好友后回访”规则。1.0.0的“每个节点独立成为顶层规则、整套规则复制”已被本版替代，只作历史；节点不是依次完成的任务流程，前一节点被排除或未完成不自动取消后续节点。第N天只在节点填写；日期维度仍可追加固定日期、相对日期或区间等限制，并与节点到期同时满足。

| 画像与推荐（5项） | 建议改善、用户特征、推荐设备/材料、推荐医生、喜好风格 |

排除另含对方发过消息、我方发过消息、双方发过消息、新加好友、和工作号同在至少一个群，共26项。“未次预约日期”在筛选维度保留来源拼写；回访基准下拉单独明确显示“预约日期”，两者原ID和日期语义不变；状态仍为正常/异常，AI需求不等于已购产品，产品映射待确认。

账号群组就是渠道归属，不是另一个员工部门。群组与指定账号取并集；搜索与全选仅影响当前结果并保留其他已选项。要挑组内部分账号，先取消整个群组。到期节点的选中条件全部满足，同一字段多值取任一；排除命中任一即排除。深圳示例以我方近2天、对方近2天两项OR表达“任一方近期联系就跳过”，不能用要求两边都发过的“双方发过消息”替代；聊天不会重置添加日期锚点。第0天、48小时、计入的消息来源继续作为已标注的演示口径，未声称生产定案。

所有变更先进入草稿，取消保持已存规则不变，保存失败保留草稿供重试；成功保存整条规则后生效，已启用规则从下一次计划时点使用新配置，不补跑。0人可保存；失效范围、缺失数据及读取失败不能降格为0。试算以固定合成样本显示到期节点、应回访、已排除、未入选和无法判断及理由。

本地v2按 `admin-revisit-rules:v2:<tenant>` 保存规则与节点结构；QA使用独立前缀，切换租户不串读账号或规则。深圳原API、稳定ID、v1/v2键与原有用户规则保持兼容，新增租户不从深圳存储初始化；原5日期规则不要求新增来源/次数字段。合法旧事件配置按anchor与anchorOccurrence配对回显成首次/最近一次直接选项；缺失或非法次数显示待修复，必须显式选择有效基准，不能自动猜值。打开/取消不迁写，新选择保存后刷新、摘要和试算保持一致。各自旧v1独立规则只读保留。发现旧数据时由使用者明确开始新版示例或逐条导入未启用草稿；只有唯一明确的日期“第N天”条件可无损转为基准与节点，其余筛选保留，歧义时说明原因，不自动合并。损坏数据不得静默覆盖。

咨询可见合同为“应回访好友集合 ∩ 当前咨询有接待权限的账号”；无账号接待权限就不能看到其好友，失去权限后也不能凭历史生成结果继续访问，多名有权咨询均可见。当前交付管理页和该权限合同；PC名单界面、真实调度、权限服务、共享数据库、发送、执行质检和完成状态协作仍未实施。
