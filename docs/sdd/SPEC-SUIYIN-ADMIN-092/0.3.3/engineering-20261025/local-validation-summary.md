## Go 服务端关键验收

1. **范围与口径**：严格隔离租户、渠道、工作号、客户关系和统计日期；区分正文与观察上下文，保留系统事件、不可读媒体和未知状态的来源，不把排除项或未知项计为成功。
2. **发布配置与追溯**：只执行已发布的渠道模板和共用规则，冻结输入、规则、模型绑定、实际协议及运行版本；草稿不执行。凭据只在受保护的服务端使用，不进入接口响应或普通日志。
3. **执行与恢复**：重复提交幂等，成功会话不重复计费；取消、重启、主机休眠和请求结果不确定时不自动重发。有限重试遵守配置及来源一致性，保留每次尝试和明确终态，报告持久化完成后才公布完成状态。
4. **独立校验**：验证结构、范围、消息引用、真实连续引文、发送方及证据可读性。提及、我方铺垫、完成转介绍及候选问题分别处理；未知不能自动成为合格或违规。历史兼容与新请求必填要求分开，必要的验证器修订可追溯且不改原回执。
5. **覆盖与运行证据**：输出应分析、成功、失败、待处理、取消、排除和未选样本的独立计数。真实用量及费用缺失时保持未知，不估造；错误分类应区分传输、格式、引用和业务复核。
6. **定时验收**：在批准恢复后，补齐双渠道两个日期的全日验证，再独立执行 04:00—08:00 时窗测试；验证跨日归属、并发预算、截止时间、异常告警及无自动重复发送。不能以本地短样本或受休眠影响的运行代替夜间验收。

## Admin 管理页关键验收

1. **双渠道页面**：企微、个微日报使用各自入口，沿用已批准布局、日期切换与工作号展示；数据与权限范围一致，未知实际接待人不得自动归责到工作号所属人员。
2. **配置与发布**：复用现有提示词编辑、发布及模型绑定；两渠道模板独立、共用规则统一引用。展示执行所用已发布版本，明确未发布草稿；手动生成不擅自修改自动调度开关。
3. **结果状态**：明确区分样本、全日、部分完成、失败、暂停、排除和未知。显示分母、覆盖及失败原因；1/1 样本不能显示为全日完成，旧结果不能掩盖本次失败。
4. **历史来源**：当前模型结果、历史协议结果和历史离线分析独立展示与追溯，不混用结论或覆盖率。刷新、返回和服务恢复后正确读取既有状态，不触发隐式新调用。
5. **证据复核**：沿用聊天证据抽屉，区分 AI 摘要和真实原文，支持定位对应消息；提及事实、我方动作和问题依据可分别核对。所有模型候选默认待复核，不把校验通过标成业务合格。
6. **操作与异常**：生成、取消、有限重试严格遵守服务端状态和预算，防重复点击；权限不足、未接入、未同步、无数据、任务失败与系统暂停分别展示。网络或主机异常不得误显示为完整成功。
