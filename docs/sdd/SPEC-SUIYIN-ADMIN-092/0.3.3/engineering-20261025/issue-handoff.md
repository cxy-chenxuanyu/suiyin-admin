## 4. 分工和接口

### I001 — Go后端

复用现有模型/Prompt/任务基础，补两个日报场景、单一共用规则与双模板发布、自然日取数和跨日响应、程序统计、结构及证据校验、输入/配置快照、持久化报告、任务幂等/恢复、权限及审计、04:00调度与08:00目标记录。旧全历史客户评分保持原行为。原始数据、用量、错误和完成状态由后端负责。

### I002 — 管理前端

按批准原型接入两个聊天管理日报页面、七模块、现有提示词六列表与两个独立模板、共用规则入口、只读模型目录、真实状态/覆盖/版本、复核与处理、账号状态人设名字映射及右侧PC只读原文时间轴。客户左、我方右，关闭恢复现场。状态、权限与完成以真实后端为准。

### 共同接口合同

Phase 1双方对齐场景/模板/规则版本、计划快照与批次/修订身份、任务进度、报告覆盖、原文证据、复核和配置发布API，至少覆盖SPEC §8.1字段语义。Go提供合同及合成响应，Admin据此并行；最终必须使用真实服务联调，不用mock宣称闭环。具体路由和数据模型由生产代码基线决定，本地Node实现只作参考。
