## 一 运营如何选择检查标准

- “检查项目与标准”展示当前企业已有项目、是否开启、简短业务标准、关注程度和编辑操作。摘要从实际生效字段生成，详情可看完整内容。
- “添加检查项目”优先提供常用标准，可查看标准和算问题／不算问题的示例后选用。通用标准与医美等行业标准明确区分，不给所有企业默认启用医美规则。
- 选用后复制到当前企业草稿，运营可以直接修改。模板库后续更新不自动改动企业已保存标准。
- 已添加的同一参考项目明确提示；需要变体时使用“复制为新项目”，生成新的稳定标识，避免重复覆盖。
- 模板仅减少首次填写负担。后续新增企业自定义项目不依赖开发人员给模板库加一条代码。
- 程序项目与AI项目分开处理：超时、深聊等标准指向现有参数页，不复制成另一项AI判断；已有固定诉求事实与服务质量问题明确各自统计口径，避免选模板后产生重复检查和同义指标。

## 二 运营如何修改标准

编辑表单围绕业务问题组织，不要求运营掌握模型协议：

| 内容 | 操作方式 |
| --- | --- |
| 检查名称 | 直接填写运营能理解的名称 |
| 什么情况算问题／怎样记录 | 提供已填标准、业务提示和例子，运营修改具体业务要求 |
| 适用情况与不计入情况 | 可选填写，明确哪些会话需要检查、哪些情况应排除 |
| 示例 | 可选补充算问题／不算问题、数值或分类示例，不强制每项都填写 |
| 关注程度 | 沿用已有普通／重点关注配置，不另加重复严重程度字段 |
| 红线候选 | 可选开启，并单独填写候选标准；人工复核后才能认定 |

常规表单不展示JSON、true、unknown、证据ID、字段编码或Schema。系统统一承担输出类型、证据归属、缺失信息、格式及校验约束。运营仍需明确本企业想检查的业务行为；不增加“AI替运营写标准”的付费功能。

固定程序统计，例如超时、深聊等，使用现有算法与数字参数控件。说明计算方法和排除条件，不提供修改一段文字就能改变算法的假入口。

## 三 运营如何新增项目

新增入口先选希望得到的结果，表单随选择变化：

1. 查找一种问题：填写问题名称、什么情况算问题，可选例外与示例。
2. 记录一个数值：填写记录内容，选择已有单位、精度和可选合理范围。现有单位为次数、分钟、天、年、百分比、元、分数。
3. 给会话分类：填写分类依据，增减分类选项，提供分类例子；首版沿用单选分类，至少一个可用选项。

运营可复制现有项目后修改，也可从带填写提示的示例开始。名称和业务标准为基本必填项；范围倒置、空分类、启用红线却没有红线标准等，在对应位置解释原因。

支持范围内的新项目保存后自动贯通后续分析输入、输出要求、校验、事实存储、指标选择和下钻，无需改源码、重新部署或逐项手改Prompt。新增数据来源、统计算法、图片视频识别、多选嵌套结果或任意脚本属于能力扩展，不能承诺任何逻辑都能通过表单实现。

## 四 保存和日常操作

- 编辑先进入本地草稿，保存整个配置前列出本次变化：只改展示、需要重算统计、影响后续分析。不给常规操作增加发布、强制试跑或额外审批步骤。
- 保存不自动启动模型，不改写历史AI原判及初始规则。已有事实支持的当前统计视图可以重算，并保留原始统计。成功后读回实际保存结果；保存失败保留草稿。
- 配置被别人更新时明确提示冲突，保留当前编辑内容，支持读取最新配置后核对，不静默覆盖。
- 离开有未保存修改的页面时提供继续编辑或放弃修改。取消编辑不落库。
- 停用项目保留历史结果；删除被统计指标引用的项目时先提示关联项，并沿用服务端依赖校验，避免留下失效统计入口。
- “参与分析”“纳入报表”“展示概览卡片”明确区分作用。关闭卡片不代表停止检查；停止一个检查项目也不等于关闭整个日报。

## 两个日报展示页面一并调整

用户继续要求检查“企微会话质检日报”和“个微会话质检日报”。本轮已实际打开深圳两个页面，查看10月29日已有历史日报和10月30日未生成状态，逐项查看七模块，并只读打开个微原文、人工复核表单与生成记录；未提交复核、跟进、统计重算、生成或补跑。两个渠道实际共用同一个列表组件，本次统一调整一套交互，数据、筛选与权限继续按渠道隔离。

**先修已确认的显示缺陷。** 问题列表与原文抽屉的判断理由为空，当前AI结果写入Explanation，接口返回explanation，前端却只读未赋值的evidencePreview。补齐类型和展示字段，显示“判断理由”；有原文摘要时单独作为真实原文引用，不能把AI解释冒充逐字原话。确实缺失的历史理由明确标“未记录”，不造内容，也不付费重跑来掩盖字段遗漏。回复时长按单位与配置精度格式化，不再展示500.03333333333336分钟等长小数，原始数值不变。

**概览先回答运营关心的问题。** 顶部保留日期、部门、工作号及紧凑的覆盖与结果状态；原始AI／复核后结果、历史显示等放入有清楚名称的查看选项。“今日概览”改为“日报概览”，明确所选日期。先展示待核实红线、需跟进诉求和问题对象，再展示分析概况；每条关注事项带工作号、客户、问题或亮点摘要、当前处理状态及查看入口。服务亮点与待处理问题分别表达。

**清楚区分未生成、部分结果和零问题。** 10月30日未生成时，现页面风险分布仍显示高／中／低风险0；改成尚未分析，不输出零风险结论。已有部分结果时，明确“当前已统计范围”，把纳入会话、符合分析条件、已分析、失败、跳过、无法判断分清；失败或不适用不能算零问题。自动定时暂停与该日报生成进度分别呈现。个微旧日报仍显示生成中是否符合实际活跃任务，要用任务元数据核实后修正，不能只改状态名称。

当前纳入会话是当日来源消息分组，成功非系统消息才计入message_count；只有系统／失败等来源记录的会话可能纳入但有效消息为0。页面应说明这一口径。实际看见的会话数大于有效消息数，不能直接当作无当日消息客户被混入，也不能凭截图认定只是旧数据。

**问题与客户列表能直接找人处理。** 问题／红线列表补工作号名称，保持客户身份、问题摘要、判断理由、程度、复核状态与处理进度清楚；布尔判断不重复显示“成立／是”。沿可见报表批量映射账号身份，避免逐行查询原文或跨企业查找。意向列表提供已分析、未分析／失败等明确筛选，默认优先呈现有判断且需处理的对象；覆盖缺口仍在顶部和专门筛选中可见，不隐藏失败。按所选指标下钻时使用业务指标名，不出现内部code。

后端普通问题列表已经限制原始status=true，不存在仅因前端未传状态就混入原始false／unknown的问题；复核后判否仍可保留追溯。本次保留该正确行为。

**看原文时就能复核和更新处理进度。** 抽屉顶部先展示本次选中问题、理由、来源工作号／客户和两个动作：“复核问题”“更新处理进度”，再展示已定位、高亮的聊天上下文。原始程序统计、其他观察结果和历史记录折叠在后，避免读完长会话才找动作。两个动作沿现有复核／处理数据模型实现；只更新处理进度不能悄悄重写AI原判、红线认定或其他复核字段。保留头像昵称、时间、撤回与不可读媒体提示，不新增识别服务或责任人猜测。

**工作号、红线、触达和标准页保持清楚。** 工作号看板先呈现工作号、部门、关键已配置指标及覆盖状态，更多指标按配置顺序展开，明确数量／比例和单位。红线模块命名为“红线复核”，分别显示候选待核实、已认定、已排除，普通严重问题不自动认定红线。产品与老带新分别说明客户提及、员工主动触达和未分析状态；缺采集不留一张含糊空表。本次检查标准默认解释本批实际采用的业务标准，当前最新配置另有明确入口，不再先堆满工作号与版本编号，不让运营用最新标准解释旧结果。

**付费与维护操作集中管理。** 普通阅读不常驻重算、生成、重新分析四个并列操作。保留生成记录入口，管理员的生成与补跑收进已有权限控制的生成管理面板，执行前明确日期、具体工作号数量、是否新增模型请求、原规则／新规则及准入方式，不能把查看筛选误当执行范围。

已核实当前手动生成会绕过自动双向5+5门槛；只选部门也不会限制执行工作号。自动定时与手动入口并非完全相同。本版建议普通手动生成与自动准入对齐，未达门槛的强制分析不作为普通运营入口；用户本次完整方案批准包含此调整：普通手动生成与自动准入对齐，不增加绕过门槛的运营入口；既有历史批次恢复仍使用原冻结来源和范围。执行面板明确工作号范围，不把部门查看筛选当执行筛选。本轮不触发生产付费操作。

可点击原型需要包含这两个菜单的实际演示内容，能完成“概览→筛选对象→问题→原文→复核／处理→返回”的主链；原先两个菜单仅弹提示的版本不算完整交付。演示仅用合成数据，与生产实跑验收分开。

## 六 数据与执行层最小调整

保留现有企业独立库、settings中的规则配置、CAS保存方式和日报五个集合。继续以工作号与统计日组织日报，保留会话事实、统计结果、证据和复核记录，不新增每项指标一张表或动态宽表。

业务表单复用已有criteria、applicability、severity、redline、数值范围和分类选项。仅按实际需要补可选业务示例；列表摘要由这些字段生成，不另存一套可独立修改、却不参与分析的“人话说明”。示例和标准一起进入冻结定义、分析输入及快照，相关变更计入版本。

必须修正已发现的版本边界：当前分类选项标签会在语义比较中被忽略。把“已预约”改成“已退款”等分类含义变化必须创建新分析版本；为避免自动猜测语义，分类标签变更统一按影响分析处理。历史结果继续按原选项和版本解释。

同类边界一起处理：当前产品名称和产品分类也会输入模型，却在版本比较中被忽略；更换名称可能实际更换识别对象。产品名称与分类变更保守地计入新分析版本。AI检查项目名称同样随定义进入模型，不一概视为展示变化。纯指标标题、排序和卡片开关仍按展示变化处理，不额外搭建语义识别服务。

排序、卡片显示等展示变化不调用模型；已有事实支持的统计调整可重算统计。新增检查和标准、适用范围、示例或分类含义变化用于后续分析，不能给历史会话补造判断。
