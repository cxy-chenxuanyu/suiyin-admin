## 字段
customer.client_wc_ids.<wcId>.friend_request_time，可空UTC date，Mongo毫秒精度。与add_friend_time同级，不在customer新增其他字段。不改变原添加时间。
ES client_customer.friend_request_time=date；不向ES索引申请凭据、原始载荷或申请人敏感内容。
申请记录侧将已有RequestAtSynthetic判据持久化，使新记录可判定真实/兜底；缺字段的历史记录不自动视为真实，只经可靠原始证据或具有真实申请时间的确定主动申请事实证明后使用。主动加友任务的创建/入队时间可能早于实际发出，仅有创建时间及已处理/已申请标记不证明真实申请时刻。原RequestAt兼容逻辑不因此改写已有业务时刻。

## 查询与响应
POST /api/v1/customers/search-list，保留所有原权限、租户、账号范围及排序。
响应friendRequestTime?:string|null（新服务始终返回该键，客户端兼容旧服务缺键），非空RFC3339 UTC时间，管理页按Asia/Shanghai格式化YYYY-MM-DD HH:mm:ss。
展开账号行读取该行ClientCustomer.FriendRequestTime；无唯一账号归属的未展开结果返回null，不从其他账号取最早/最近时间冒充此行。
clientTimeRanges可增加{field:"friend_request_time",startTime:"2026-11-19T16:00:00.000Z",endTime:"2026-11-20T15:59:59.999Z"}表示北京时间2026-11-20全天，gte/lte。普通现有字段规则保持兼容，不修改共用日期范围语义。
管理页日期必须完整且start<=end，新字段接口非法时间范围返回400。未传条件不增加过滤；字段为空的关系不匹配任何已提供日期边界。前端不发请求补查pendingFriendRequests后自行拼页。
多个时间与账号/关键词/原条件按同一展开关系AND；分页total与导出使用同一后端查询。

## 双向关联及安全写入
申请事实先落pending_friend_requests；不因未通过申请提前创建客户。
客户账号关系建成/确认通过后补申请时间；申请事实迟到/补齐/确认通过后反查已有关系，两边使用同一判定。
需要同租户、账号身份、对方身份、已确认通过、本轮关系可验证和时间可靠。旧轮次/重复回调/未知通过状态/身份不一致拒绝覆盖。新一轮已建成但无可靠申请时间时unset旧值，未通过的新申请不得清掉旧关系时间。
复用既有FriendAcceptedEventID/CycleToken与条件更新，按真实路径确保读后写并发安全；对不具备周期证明的路径留空，不能以当前状态friend推断一定同轮。普通资料刷新/深拷贝/窄更新/同步不得覆盖已确认值。中途失败保留可恢复事实；恢复仅复用适用既有后处理，不新增timer/监听。
同一既存周期补空需有该关系与申请编号/轮次的可靠绑定；Round为0不单独证明同轮，未观察删除也不因新申请重设既有关系周期。辅助记录即使字段齐全，来源若为外部通知的宽匹配，也不能提升为精确申请证明。申请时间与添加时间各自独立：已有精确通过证据且申请时间可靠时，添加时间为空不妨碍申请时间补齐，也不得因此填写添加时间。外部已通过而附加metadata步骤失败时保留已通过事实，只沿适用的原已通过补建入口恢复；派发不等于实际恢复成功，不重复外部通过或已完成的后处理。
个微回调的申请凭据可能非最终客户wxid，企微FromWxId为contactID，必须依服务商已有身份映射，不用昵称猜匹配。
