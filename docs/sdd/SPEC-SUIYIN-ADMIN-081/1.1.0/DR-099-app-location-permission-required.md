# DR-099：APP 位置权限为使用前置条件，扫街页面不展示定位

## 状态与来源

- **状态**：已采纳，2026-10-12 房总直接批准记录。
- **来源**：本次 APP 扫街人模式需求与房总对 SPEC-APP-080 草稿的明确纠偏。
- **用户原话**：“前端不用展示定位，也不用上报，但是不让获取地址，整个碎银不能使用，这个记个DR给后端和前端工程师这个机制就好了，其它OK的”。
- **关联规格**：[SPEC-APP-080@1.0.2](https://github.com/xfang9528-glitch/suiyin-app-chat/blob/v2026-10-12-app-street-promoter/docs/sdd/SPEC-APP-080/1.0.2/spec.md)，R007、R008；本地源为 `E:/AI 项目/prototype-sdd/specs/080-app-street-promoter/spec.md`。
- **APP工程跟踪**：[flutter-suiyin #8116](https://github.com/PetWebOrg/flutter-suiyin/issues/8116)，负责人王梓先（build996），仅APP、全部APP租户；正式能力待工程实现及验收。

## 背景

房总要求管理页定义为扫街人的销售打开 APP 后直接展示分配给自己的可接待工作号二维码，支持点击放大和多张切换；最初同时提出后台定位、每 30 秒上报的位置背景需求。

首轮草稿将位置状态、上报时间、周期与异常恢复放入原型。房总随后明确取消前端位置展示与前端上报职责，并要求将“未允许获取位置则整个碎银不能使用”的机制记录给前后端工程师。本决定替代草稿的位置 UI、模拟上报/周期及“定位异常仍能使用二维码”等提案。

## 已确认决定

1. **正式碎银 APP 的使用以允许获取位置为前置条件。** 用户未允许获取位置时，整个 APP 的业务功能都不能使用，不能只禁用扫街二维码页后仍放行聊天或其他普通入口。这里的“地址”按本次上下文指设备位置信息，不是要求填写邮寄地址。
2. **前端页面不展示定位信息。** 扫街二维码页不增加位置、定位成功/失败、最后上报时间、30 秒倒计时等内容。
3. **前端不承担位置上报职责。** 不把定时上报、位置补报或上传流程安排进扫街展示页；前端页面无上报并不意味着位置来源可以省略。
4. **本轮仅记录机制，不实现位置门槛。** HTML 原型不申请真实位置权限、不采集位置、不上传真实或模拟位置、不启动位置计时器，也不制作位置权限阻断页面。原型能展示二维码不能证明正式 APP 已通过该前置条件。
5. **当前范围是本次碎银 APP 整体。** 不将“整个碎银”自行扩展为 PC 或 Admin 的新权限要求；跨端范围若要变化需另行明确。
6. 原型外“常规模式 / 扫街人模式”仅用于演示；正式 APP 由管理页角色进入，不能用原型演示开关规避正式位置使用门槛。

## 前后端工程必须共同落实的事项

以下是正式实现前必须明确的工程合同，当前未选定实现方式，也未声称已完成：

| 事项 | 需要明确的结果 | 边界 |
|---|---|---|
| 真实位置来源 | 哪个设备/系统能力或已存在的合规终端通道取得当前位置，位置与当前租户及登录人员如何关联 | 不得假定服务端无需终端来源即可取得设备位置；不得把IP推断默认等同于用户要求的位置 |
| 终端与服务端责任 | 前端页面、终端系统能力、独立后台组件和服务端各承担哪些检查/获取/传输/接收职责 | 用户已取消前端页面展示与上报；实现分工需说明真实数据从何而来 |
| 原30秒背景要求 | 将最初“后台实时定位，每30秒上报一次”与本决定共同核对，明确正式链路、周期及系统限制 | 本决定不把30秒改为前端定时器，不以浏览器Mock验证正式后台可靠性 |
| 权限检查与入口保护 | 首次进入、恢复前台、权限撤销后如何检查并阻止全部APP业务入口；允许后怎样恢复 | 不可只隐藏二维码UI而从其他入口绕过；不以旧权限缓存默认为当前有效 |
| 拒绝与其他异常区分 | 拒绝/未授权、系统定位关闭、设备暂时取不到位置、断网等各属于哪种状态 | 用户已明确“未允许获取位置不能使用”；不能未经确认把所有网络故障或定位失败都等同于拒绝权限 |
| 会话与后台边界 | 开始/结束条件、退出登录、角色变化、后台/锁屏、进程终止的真实行为与限制 | 不保留草稿按会话持续跨天、首次即上报或恢复密集补发等未经采用的具体策略 |
| 数据范围与验证 | 租户/人员隔离、位置查看权限、保留周期及可复核证据 | 本轮无管理地图/轨迹页面，也不保存真实经纬度 |

“前端不用上报”是已确认的产品责任边界；真实位置链路如何满足该边界必须由工程团队核实，不能将未明确的采集/传输方案写成现有能力。

## 对本轮原型的影响

- 保留二维码、名称、序号、下一张、放大/关闭、空/错误恢复和轻量退出登录。
- 删除全部定位展示、位置模拟场景、周期计时、上报成功/失败、定位异常仍可使用的旧规则。
- 位置使用门槛不在 HTML 中实现；文档核对只能证明决定已记录。
